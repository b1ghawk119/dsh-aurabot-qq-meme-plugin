# 1.3.0：自动首次准备

- 新的轻量安装只需放入完整模块代码目录。启动时自动准备平台依赖及 732 个基础模板；面板显示阶段进度、失败重试，扩展仍为可选。已有完整安装复用原路径，不搬动或重新下载资源。
- 素材采用固定版本/提交的整库归档、流式解压。基础库每库一次归档请求，不逐素材请求 raw/GitHub API；Python 扩展也共用归档路径，并排除已由基础库提供的资源。源码与素材路径中的中文由公共解包逻辑处理。
- npm 组件使用提交在清单中的 SHA-512 完整性值验证后落盘。安装任务持有运行目录锁，热重载/停止会回收自有准备进程，失败后可重试。
- Windows 实机测试使用没有组件、没有完成标记的独立缓存：真实下载 3 个 npm 组件；大素材库通过硬链接复用以避免重复下载约 1 GiB，完成初始化、732 个目录加载、一次模板生成和重载复用。期间发现 Windows raw 连接重置，最终方案已取消逐文件补齐；归档传输以小型 UTF-8 样本独立验证，一次 HTTP 请求解出多个中文路径文件，无压缩包残留。
- Windows Edge 检查真实面板：准备进度、失败提示、重试按钮、完成后模板列表出现，控制台无错误。失败/重试界面使用受控状态测试，不额外下载整库。
- Windows 公共测试 42 项通过，包括完整性失败、缓存复用、锁互斥、停止后不回写、中文归档、持久缓存离线打包、错误不外泄及已有功能回归。macOS/Linux 仅保留适配，未测试。
- 已热加载到当前 AuraBot：ready=true、1005 个模板，原 273 个扩展保持启用，准备状态为 ready；已就绪时点击重试为无操作。

新缓存位于模块数据目录的 runtime/node_modules 下，更新代码可复用；原有完整离线目录继续可用。打包器兼容两种布局，可按原命令打包，也可显式指定 --runtime-dir。

自动准备依赖属于需要维护者审核的分发行为；本版本尚未发布到官方模块市场。
